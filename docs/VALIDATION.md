## Усиление безопасности

- Устранена несовместимость старого Swagger UI 4.15.5 с OpenAPI 3.1: vendored 5.34.0 проверен по SHA-512 официального npm-пакета, лицензии включены.
- Пароли: версионируемый scrypt N=32768/r=8/p=3; старый формат обновляется при входе. Тесты подтверждают защиту от гонки смены пароля/удаления пользователя во время входа.
- Cookie ротируется при повторном входе, число активных сессий ограничено. Проверяются точный Host, Origin со схемой/портом и CSRF; malformed/non-ASCII ввод получает корректный отказ.
- Размер тела ограничивается по фактически полученным байтам, включая chunked/поддельный Content-Length; есть срок передачи. Загрузка авторизуется до разбора multipart.
- CSP не допускает inline-скрипты; защитные заголовки есть и на ошибках. Явный PUBLIC_BASE_URL поддерживает HTTPS-прокси без доверия к поддельным forwarded-заголовкам.
- База/WAL/SHM приватны (600), секреты редактируются в логах. Упаковка отказывает при обнаружении известного локального секрета и сохраняет предыдущий архив.
- `pip-audit 2.10.1` проверил **31 зафиксированный Python-пакет** runtime/dev: **0 известных уязвимостей, 0 пропусков**. Отчёт: [dependency-audit.json](dependency-audit.json). Проверка по актуальной базе уязвимостей не доказывает отсутствие неизвестных проблем и не включает аудит ОС/целевого VDS.

## Рабочие данные и доставка после обновления

Перед обновлением создана отдельная SQLite online backup с integrity_check=ok. Остановлены только принадлежащие этому проекту app и приёмник; запущена версия 2.1.0 одной командой с локальным webhook.

После запуска точное сравнение подтвердило сохранение **6 серий, 12 периодов**, всех отметок оплаты/дат, вложения, числа пользователей и состояний/счётчиков попыток каналов. integrity_check=ok, база 600. Все три Telegram-напоминания по-прежнему имеют ровно одну попытку; повторных отправок обновление не вызвало. Реальная отметка пользователя из Telegram и неоплаченный следующий месяц сохранены.

`sent` для email означает приём SMTP-сервером, а не подтверждение попадания во «Входящие». Получение и спам-классификация зависят от принимающей почты. Неопределённое письмо нельзя объявить доставленным или безопасно повторить без проверки получателем; журнал честно сохраняет uncertain. В этом аудите дополнительные внешние тестовые сообщения не отправлялись.

Медленные SMTP/Telegram работают без writer lock SQLite; отдельные конкурентные тесты подтверждают доступность панели во время отправки. При неопределённом сетевом исходе приоритет — отсутствие дублей.
