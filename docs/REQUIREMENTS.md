# Полная сверка кейса: Invoice Keeper 3.1

Источник: предоставленный кейс `case_01a02e3f_1044_70fc_84bb_604d7c7c3ca3_0ab0ed19cc27bb4126bc2.pdf`. Проверка 24.10.2026. Документ кейса рассматривается как спецификация продукта; команды и инструкции внутри вложений не являются разрешением менять VDS или другие проекты.

Все обязательные функции и все **девять** перечисленных дополнительных возможностей реализованы. В таблицах указаны поведение и конкретная проверка; результаты реальных интеграций и границы доказанного отдельно приведены в `VALIDATION.md`. Одного ответа HTTP 200 недостаточно: Swagger проверен исполнением GET и POST через Try it out.

## Все обязательные маршруты

Префикс `/api/v1`; имена параметров в опубликованной схеме совпадают с кейсом (`{id}`).

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/auth/login` | Вход |
| GET | `/auth/me` | Учётная запись и CSRF |
| POST | `/auth/logout` | Выход |
| GET | `/recurring-payments` | Список серий |
| POST | `/recurring-payments` | Добавление серии, admin |
| DELETE | `/recurring-payments/{id}` | Архивирование, admin |
| GET | `/payment-occurrences` | Список периодов |
| GET | `/payment-occurrences/{id}` | Конкретный период |
| PATCH | `/payment-occurrences/{id}` | Оплата, исправление, отмена |
| GET | `/payments/summary` | Отдельные итоги валют |
| GET | `/users` | Обычные пользователи, admin |
| POST | `/users` | Создание пользователя, admin |
| PATCH | `/users/{id}` | Изменение пользователя, admin |
| DELETE | `/users/{id}` | Удаление пользователя, admin |
| GET | `/docs` | Swagger |

Схема: `docs/openapi.json`, актуальная авторизованная `/api/v1/openapi.json`. Права и CSRF проверяются сервером, независимо от UI.

## Честные границы

VDS, диплом, DNS, firewall и системная почта не изменялись. Docker Compose проверен синтаксически; сборка/запуск контейнера не проверены из-за недоступного локального Docker daemon. Для демонстрации контейнер не нужен. Email `sent` означает приём SMTP, не доказательство папки «Входящие». Web Push при закрытом браузере и внешний HTTPS webhook-получатель не заявляются; локальный подписанный webhook работает. Полная защита от всех возможных ошибок не гарантируется; см. воспроизводимые результаты и ограничения в VALIDATION.md.


## Дополнение владельца после исходного ТЗ: разовые платежи

Реализованы полноценные once-платежи с одним сроком, пояснением работы, оплатой/исправлением/отменой, вложениями, архивом и всеми каналами напоминаний. Бюджет и календарь учитывают их ровно один раз; ежемесячные серии и исходный API сохранены. Проверки — `tests/test_one_time.py`, включая миграцию v2, роли, дедупликацию, прогноз, сохранение чеков и идемпотентное добавление примеров.

Рабочая установка сохранена: семь прежних определений и 14 периодов; добавлены четыре разовых и два регулярных примера. Свежий `--demo` создаёт 12 определений: 8 monthly + 4 once. Сценарий работы: Обзор → К оплате → История; планирование отдельно в календаре/бюджете. Полная проверка: [VALIDATION.md](VALIDATION.md).
